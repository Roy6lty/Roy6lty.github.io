How I work

Understand the path.
Leave evidence behind.

The recurring pattern in my work is to connect product behavior to the system underneath it, then make that system easier for the team to operate and change.

01 / CONTEXT

Trace the real user action.

Start with what a person is trying to accomplish, then follow the data, services, states, and dependencies needed to make that action reliable.

02 / EVIDENCE

Debug from what the system shows.

Logs, metrics, packets, routes, database state, and repeatable experiments are more useful than guessing which layer is responsible.

03 / OWNERSHIP

Stay with the work after merge.

Release paths, health checks, migrations, documentation, and recovery are part of the engineering work, not somebody else's problem after the feature ships.
